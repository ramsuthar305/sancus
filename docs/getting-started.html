Get it running

Two ways. Docker Compose starts the gateway with Redis in one command. Node plus a local Redis works too.

With Docker

git clone https://github.com/ramsuthar305/sancus.git && cd sancus
docker compose up
curl -i localhost:3000/health/ready

You get {"status":"UP"} once the config is loaded and Redis answers. The compose file mounts api_configs/, so you edit YAML on your machine and the gateway picks it up.

With Node

npm ci && npm run build
cat > .env <<'ENV'
YOUR_SERVICE_HOST=http://localhost:8000
AUTH_URL=http://localhost:8001
REDIS_URL=redis://localhost:6379
ENV
npm run check      # validates api_configs/
npm start

npm run dev restarts on every change while you work on the gateway itself.

Your first service

  1. Start something on port 8000 that answers HTTP. A one-line Python server is enough: python3 -m http.server 8000.
  2. Open api_configs/your_service_name.yml. It already points at YOUR_SERVICE_HOST. Set that variable to http://localhost:8000.
  3. Send a request through the gateway: curl -i localhost:3000/api/your_service_name/v1/public/search.
  4. Look at the headers. X-Request-Id, X-RateLimit-Remaining and X-Cache-Status: MISS tell you the gateway did its work. Send it again and the cache answers.

Your own auth

Routes without bypass: [AUTH] need a token. Sancus sends the token to AUTH_URL and expects a 2xx with an id field. If you already have a token introspection endpoint, set five variables and you are done. The auth page has the full contract and examples for services that use a header instead of a body, or a nested id.

No verifier yet? Start with everything on bypass: [AUTH], or set AUTH_FAIL_OPEN=true while you build one.

Behind a load balancer

Set TRUST_PROXY before you go live. The default trusts private addresses, which covers an ingress or ALB inside your network. If your proxy has a public address (Cloudflare, for instance), list its ranges. With the wrong value every user shares the balancer's IP and the per-IP limiter throttles the whole site. Sancus refuses to start with TRUST_PROXY=false while the IP limiter is on, for that reason.

Kubernetes

kubectl apply -k k8s/

The manifests include a ConfigMap, an example Secret, readiness on /health/ready, resource limits, an HPA and a PodDisruptionBudget. Change the image tag, the hosts, and the upstream URLs. The operations page covers what to watch once it runs.
