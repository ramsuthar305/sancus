Chapter 3

Follow one request.

A phone asks Kettle for order 881. The request carries id 7f3a. Here is everything that happens to it between the internet and the orders service.

GET /api/orders/v1/orders/881 HTTP/1.1 Host: api.kettle.example Authorization: Bearer eyJhbGciOi… X-Request-Id: 7f3a0c2e-51d4-4b8e-9d1a-2c6f0e7b3a19 X-Forwarded-For: 203.0.113.44

Station 1. Which door is this?

Sancus reads orders from the path and looks up orders.yml. The rest, /v1/orders/881, matches the route /v1/orders/{int:id} for GET. If the path had been /v1/orders/abc, the int type would refuse it and the phone would get 404. A DELETE would get 405 with Allow: GET, HEAD.

The routes were compiled when the file loaded. Matching is a loop over ready patterns. Nothing touches the disk.

Station 2. House rules

Orders has no policies. If it listed ip-restriction or a policy of Kettle's own, they would run here, and any of them could answer the phone and end the story. Policies shows how to write one.

Station 3. Where are you, and who are you?

Two checks start together. The geo-fence is off at Kettle, so it passes at once. The auth check hashes the token and asks Redis if it has seen it in the last minute. It has not, so Sancus calls the verifier:

POST http://auth.internal:8001/v1/verify/token X-Forwarded-Method: GET X-Forwarded-Uri: /api/orders/v1/orders/881 X-Forwarded-For: 203.0.113.44 {{"token":"Bearer eyJhbGciOi…"}} 200 {{"id":"u_1932","role":"customer"}}

Sancus caches that answer for sixty seconds. The phone polls every ten seconds while the rider is on the way, so the verifier hears from this user once a minute instead of six times.

Station 4. How many is too many?

This route has no rateLimit, so the request walks past. On POST /v1/orders Sancus would run one Lua script in Redis for the 30-a-minute window keyed by u_1932, and get back allowed, remaining and reset in one round trip.

Station 5. Do we already know the answer?

No cache block on this route either. An order changes while it is being delivered, so Kettle does not cache it. On search, with a cache block, a repeat request would end here as X-Cache-Status: HIT in under three milliseconds.

Station 6. Through the door

Sancus picks orders-b, the next node in the rotation, and sends the request over a connection it already has open:

GET /v1/orders/881 HTTP/1.1 Host: orders-b:8080 X-Request-Id: 7f3a0c2e-51d4-4b8e-9d1a-2c6f0e7b3a19 X-AUTHORIZED-FOR-ID: u_1932 X-Forwarded-For: 203.0.113.44, 10.0.4.17 X-Forwarded-Proto: https 200 {{"id":881,"status":"out_for_delivery"}} 14 ms

The response streams back to the phone with the same request id. One JSON log line records the whole trip, and every other log line about this request, in the gateway and in orders, carries 7f3a.

What each station costs

One gateway process on a laptop, 100 connections at once. Chapter 5 has the method.

21,398req/s, stations 1 and 6 only
18,313req/s with a rate limit
18,722req/s with a cached token check
32,376req/s answered from cache

Each Redis-backed station costs about 13 percent. A cache hit beats a plain proxy because the upstream drops out of the picture.
