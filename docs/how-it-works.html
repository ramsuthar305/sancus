How a request flows

A request to /api/<service>/<path> walks six stations. Each one can end the request early. Nothing reaches your service until all of them pass.

1. Match

Sancus takes the service name from the URL and finds the route in that service's file. Exact paths win over paths with parameters, whatever order you wrote them in. An unknown path gets a 404. A known path with the wrong method gets a 405 and an Allow header. HEAD works wherever GET does.

Routes are compiled when the file loads, so matching is a loop over precompiled patterns. No I/O.

2. Policies

If the service or the route lists policies, they run now. A policy is an Express middleware with a name and a schema. Sancus ships ip-restriction. You add your own by dropping a file in policies/. See policies.

3. Geo-fence and auth, in parallel

For anonymous cached routes, Sancus looks in the cache first and skips this station on a hit. Otherwise two checks run at the same time. The geo-fence check reads X-COORDINATES and rejects points inside a banned polygon. It is off until you ship polygons. The auth check sends the bearer token to your verifier, unless the route has bypass: [AUTH]. Valid tokens are cached in Redis for sixty seconds, so a busy user costs one verifier call a minute.

4. Rate limit

The route's rateLimit block names a window and a key. Sancus runs one Lua script in Redis per window and gets back allowed, remaining and reset. The day window runs before the minute window, so a daily rejection does not burn a minute token. If Redis is down, the request goes through.

5. Cache

For cached GET routes, Sancus looks up the entry. A hit answers from Redis with X-Cache-Status: HIT, an Age, and an ETag. If the client sent a matching If-None-Match, it gets a 304 and no body. With the SWR strategy a stale entry is served at once and refreshed in the background.

6. Proxy

The request goes to an upstream node over a keep-alive connection. Sancus strips hop-by-hop headers, sets Host to the node, appends to X-Forwarded-For, and adds X-Request-Id plus the user id from step 3. On the way back it strips hop-by-hop headers again, streams the body, and stores it if the route is cached and the upstream did not say no-store.

Connection errors go to the next node and are retried once for GET, HEAD and OPTIONS if the service allows it. A node that refuses connections is skipped for thirty seconds. A timeout becomes a 504. Enough failures in ten seconds open the circuit breaker, and the service gets a 503 with Retry-After until it recovers.

What each station costs

Measured on a laptop with one gateway process and 100 concurrent connections. The benchmark page has the method and the full tables.

PathRequests per second
Plain proxy, access log on16,600
Plain proxy, access log at warn21,400
Plus a rate limit18,300
Plus auth with a cached token18,700
Cache hit32,400

Each Redis-backed feature costs about 13 percent. A cache hit costs less than a proxied request because the upstream is out of the picture.

WordMeaning
