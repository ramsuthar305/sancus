Running in production

Sancus tells you when it is ready, exposes Prometheus metrics, logs one JSON line per request with a request id, and drains cleanly on SIGTERM.

Endpoints

EndpointPurpose
GET /healthLiveness. 200 while the process runs.
GET /health/readyReadiness. 503 until the config is loaded and Redis answers, and again during shutdown. Point your readiness probe here.
GET /metricsPrometheus text
GET /routesLoaded services, routes and policies
DELETE /cache/:servicePurge the response cache for one service

Set ADMIN_TOKEN and the last three require Authorization: Bearer <token>. The health endpoints stay open for probes.

Logs

One JSON line per request from pino, with requestId, method, URL, status and response time. Every other log line inside that request carries the same id. authorization, cookie and set-cookie are masked; add to the list with LOG_HEADERS_REDACT, or drop headers entirely with LOG_HEADERS_DROP. The access log at info costs about 20 percent of throughput; many teams run LOG_LEVEL=warn and rely on metrics.

Trust proxy

Sancus learns the client's IP from X-Forwarded-For only when the direct peer is a proxy it trusts. The default, loopback, linklocal, uniquelocal, trusts private addresses, which is where an ingress or a cloud load balancer sits inside your network. A public client cannot forge the header, because its own address is not private.

ValueUse when
defaultthe balancer or ingress has a private IP
1exactly one proxy in front, wherever it is
10.0.0.0/8, 173.245.48.0/20proxies with public addresses, such as Cloudflare; list their ranges
falseno proxy at all; refused while the IP limiter is on

Shutdown

On SIGTERM the readiness endpoint turns 503, the listener closes, in-flight requests finish, idle keep-alive connections are closed, and the process exits. SHUTDOWN_TIMEOUT_MS (10 s) caps the wait. Set the pod's terminationGracePeriodSeconds above it.

Workers

WORKERS=4 forks four gateway processes sharing the port. Limits and the cache live in Redis, so workers do not disagree. The breaker and alert cooldowns are per worker. Use the pod's CPU limit as the count.

Kubernetes

kubectl apply -k k8s/

The kustomize set has a namespace, a ConfigMap for settings, an example Secret for REDIS_URL and ADMIN_TOKEN, a Deployment with readiness on /health/ready, resource requests and limits, a non-root security context, a ClusterIP Service, an nginx Ingress with the ALB annotations in comments, an HPA on CPU, and a PodDisruptionBudget. Keep the balancer's idle timeout below KEEP_ALIVE_TIMEOUT_MS.

Alerts

ALERT_WEBHOOK_URL takes a Slack or Discord incoming webhook. Sancus posts on upstream 5xx, proxy errors, rate-limit breaches, IP blocks, breaker opens and rejected config reloads, at most once per ALERT_COOLDOWN_MS per event. For anything beyond that, alert on the metrics.
