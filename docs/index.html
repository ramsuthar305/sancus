One door in front of all your services.

Sancus is an API gateway written in Node. You describe each service in one YAML file. Sancus checks the token, applies the rate limit, answers from cache when it can, and forwards the rest.

Run it in five minutes See how a request flows

The problem it solves

You have three services. Each one checks tokens its own way. Two of them have a rate limiter, one does not. Nobody remembers which one caches. A new service joins and copies whichever pattern its author found first.

Put Sancus in front, and those jobs happen in one place. Your services receive a request that already has a verified user id on it, a request id for the logs, and a guarantee that the caller is inside their quota. The service code gets smaller.

What a request goes through

Every request walks these stations in order. A cache hit stops at station five and never touches your service. Read the full walk for what each station does and what it costs.

What you get

One file per service

Routes, methods, auth, limits and cache in one YAML file. Sancus checks it against a schema and reloads it when you save.

Your own auth

Sancus calls the token verifier you already have. A 2xx with a user id means valid. Anything else goes back to the client as is.

Two rate limiters

A per-IP bucket for everyone, and per-route windows keyed by user, IP or API key. Both in Redis, so every pod sees the same counts.

A real cache

LRU, LFU or stale-while-revalidate per route. Standard headers, 304 answers, and it respects what your service says in Cache-Control.

Failure handled at the edge

Several upstream nodes, retries, a circuit breaker and timeouts. A slow service gets a 504, not a hung client.

Runs like a grown-up

Readiness that means it, Prometheus metrics, JSON logs with request ids, graceful shutdown, an 80 MB image.

A service in twelve lines

service:
  name: users
  nodes: [http://users-a:8080, http://users-b:8080]
  timeout: 5000
apis:
  - name: Users
    routes:
      - path: /v1/users/{int:id}
        methods: [GET, PATCH]
      - path: /v1/public/search
        methods: [GET]
        bypass: [AUTH]
        rateLimit: { perMinute: 120, key: IP }
        cache: { strategy: SWR, ttl: 300, key: PATH_QUERY }

Drop that in api_configs/users.yml. Requests to /api/users/v1/users/42 now need a valid token, and /api/users/v1/public/search is public, limited to 120 a minute per IP, and cached for five minutes.

Who should not use it

If your gateway has to do more than 50,000 requests a second on one machine, use APISIX or Kong. They run on nginx and they are faster per core. The benchmark page shows the numbers side by side, with Sancus in last place on raw throughput. Sancus is for teams that want the setup to take an afternoon and the config to fit in their head.
