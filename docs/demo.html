The practice run.

Before Kettle put Sancus in front of real customers, the team ran it against a fake platform on a laptop. That platform ships in demo/: an auth service, a users service, two copies of a catalog service, Redis, and a script that walks you through seventeen requests.

Run it

cd demo
docker compose up --build
./tour.sh          # in another terminal

Without Docker: ./demo/run-local.sh from the repo root, with Node 18+ and a local Redis.

What the tour shows

Request idsa request with X-Request-Id: tour-0001the same id in the response and in the upstream's echo

Cachethe same GET three timesMISS, HIT with Age and ETag, then 304
Stale-while-revalidatea GET after the entry agedSTALE served at once, HIT with fresh data next
Rate limitsix calls on a 5-a-minute routeX-RateLimit-Remaining counting down, then 429 with Retry-After
Replicasfour uncached GETsservedBy alternating between the two catalog copies
Timeouta route that takes 2.5 s on a 1.5 s limit504 after 1.5 s
Streamingan SSE routefive events with timestamps 400 ms apart
Policiesa POST without a header400 from a policy you can read in eight lines
Breakera route that always fails500s, then 503 from the gateway with Retry-After
Hot reloada new YAML file dropped inthe new service answers; a broken file is rejected and the old config stays

Keep the service logs open while you go. The auth log shows one call per token, the catalog logs show which requests never reached the service.

After the tour

  • Change a TTL in demo/api_configs/catalog.yml and save. The next request uses it.
  • Stop catalog-b and call the replicas route. The first call retries onto catalog-a, then b is skipped for thirty seconds.
  • Copy demo/policies/require-header.js, rename it, and reference it from a route.
