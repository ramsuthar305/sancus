Service config.

One YAML file per service in api_configs/. Sancus validates it against a JSON Schema at start and on every change. npm run check validates without starting.

Kettle, week three

The api_configs folder has three files now: menu.yml, orders.yml and search.yml. The team reviews them like code, because they are. This page lists every field those files can use.

A full file

service:
  name: users                       # URL prefix: /api/users/...
  nodes: [http://users-a:8080, http://users-b:8080]
  # host: USERS_URL                 # older form: env var with the base URL, plus port:
  hosts: [api.example.com]          # optional Host allow-list
  rewrite: { from: "^/v1", to: "" } # regex on the upstream path
  timeout: 10000                    # ms waiting for upstream headers, default 60000
  retries: 1                        # GET/HEAD/OPTIONS on connection errors, default 0
  circuitBreaker: { errorThresholdPercentage: 50, volumeThreshold: 10, resetTimeout: 30000 }
  headers: { add: { X-Gateway: sancus }, remove: [Cookie] }
  policies:
    ip-restriction: { allow: [10.0.0.0/8] }

apis:
  - name: Users
    routes:
      - path: /v1/users/{int:id}
        methods: [GET, PATCH]
      - path: /v1/public/search
        methods: [GET]
        bypass: [AUTH, GEO_FENCE]
        resolveUser: true
        rateLimit: { perMinute: 120, perDay: 5000, key: USER_OR_IP, group: search, hideHeaders: false }
        cache: { strategy: SWR, ttl: 300, key: PATH_QUERY, browserTtl: 60, varyHeaders: [Accept-Language], statusCodes: [200, 404] }
        headers: { add: { X-Route: search } }
        policies:
          require-header: { header: X-Client }

${VAR} and ${VAR:-default} anywhere in the file are replaced from the environment before parsing. That is how the demo uses one file for local and Docker node lists.

service

FieldDefaultWhat it does
namerequiredLetters, digits, _, -. Becomes the first path segment after /api/.
nodesUpstream base URLs. Round-robin. A node that refuses connections is skipped for UPSTREAM_UNHEALTHY_TTL_MS.
host, portThe older single-upstream form. host names an environment variable holding the base URL. Use nodes for new files.
hostsanyOnly requests whose Host header is in the list reach this service. Others get 404.
rewritenoneA regex and replacement applied to the path after /api/<name> is stripped.
timeout60000Milliseconds to wait for upstream response headers. Then 504.
retries0Extra attempts on connection errors, idempotent methods only, next node each time.
circuitBreakeroffOpens when at least volumeThreshold calls in the last ten seconds had more than errorThresholdPercentage failures. Stays open resetTimeout ms, then tries one request.
headersnoneRequest headers to add or remove before proxying. Route-level rules apply after service-level.
policiesnoneNamed policies with their config. See policies.

routes

FieldDefaultWhat it does
pathrequiredStarts with /. Parameters look like {int:id} or {str:slug}. Exact paths beat parameterised ones.
methodsrequiredOne or more of GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS. HEAD is implied by GET.
bypassnoneAUTH makes the route public. GEO_FENCE skips the coordinate check.
resolveUserfalseOn a public route, still identify the user when a token is present.
rateLimitnoneSee rate limiting.
cachenoneSee caching.
headers, policiesnoneSame as on the service, for this route only.
