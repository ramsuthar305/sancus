Where it fits

Sancus makes sense when the gateway is one of many things you run, not the thing you run. Three stories, then the honest counter-cases.

A product team with a handful of services

You run an API, a search service and a payments worker. Each has its own auth check, copied from the last one. You add Sancus, point it at your existing token endpoint, and delete the auth middleware from all three. The services trust X-AUTHORIZED-FOR-ID and stop caring about tokens.

The search route gets cache: { strategy: SWR, ttl: 300 }. Search traffic to the service drops by most of its volume and users stop seeing the slow query. Payments gets rateLimit: { perMinute: 10, key: USER }, which nobody had time to write before.

A mobile app backend

Ten thousand phones poll the same feed. Sancus caches the feed per path, serves 304 to phones that already have it, and puts Cache-Control: public, max-age=60 on the response so the phones stop asking for a minute. The feed service sees one request a minute per feed instead of ten thousand.

The IP limiter handles the odd device stuck in a retry loop. The per-user limiter on the upload route stops one account from filling the queue. Both limits live in Redis, so adding a second gateway pod does not double anyone's quota.

An internal platform

Five teams, each shipping a service, each wanting a route. Every team owns one YAML file in api_configs/. The platform team owns the gateway, the auth verifier, and the policy folder. A team that needs a rule nobody else has writes it as a policy in a few lines, and the config check runs in their pull request.

/routes lists what is live. /metrics shows requests per service and route. A broken YAML never reaches production because the gateway refuses to load it.

When to pick something else

You needUseWhy
More than about 50k requests a second per nodeAPISIX, KongNginx-based gateways do 4 to 7 times the throughput per core. See the numbers.
JWT validation without a verifier serviceKong, Traefik, APISIX, KrakenDSancus calls a verifier. It does not check signatures itself.
Kubernetes Gateway API CRDsEnvoy Gateway, TraefikSancus reads YAML files, not cluster resources.
Request and response body rewritingKrakenD, APISIXSancus forwards bodies untouched. You can add a policy, but there is no built-in transformer.

Sancus is the right size when one person can read the whole config and the whole gateway in an afternoon.
