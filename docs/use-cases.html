Chapter 4

Three teams.

Kettle came to Sancus after a bad night. Two other teams came with different problems. Here is what each one had, what each one wrote, and what changed.

Kettle: search that kept timing out

Two weeks after hour one, search slows down every evening. The query behind "restaurants near me" takes 900 ms, and at dinner time the service sees 400 of them a second. Most are the same forty neighbourhoods.

- path: /v1/nearby
  methods: [GET]
  bypass: [AUTH]
  cache: { strategy: SWR, ttl: 120, key: PATH_QUERY, varyHeaders: [Accept-Language] }

Search now sees one request per neighbourhood and language every two minutes. When an entry gets old, the next user still gets an instant answer marked STALE, and Sancus fetches a fresh one behind them. The 900 ms query is still slow. Nobody waits on it.

Tally: ten thousand phones asking the same thing

Tally is a habit-tracking app. Every phone asks for today's challenge when it opens, and again every minute while it stays open. The challenge changes once a day.

- path: /v1/challenge/today
  methods: [GET]
  bypass: [AUTH]
  cache: { strategy: LRU, ttl: 300, key: PATH, browserTtl: 60 }

browserTtl: 60 puts Cache-Control: public, max-age=60 on the answer, so a phone stops asking for a minute. When it asks again it sends the ETag, and Sancus answers 304 with no body. The challenge service went from thousands of requests a minute to one every five minutes. Tally also caps uploads at 20 a minute per user, which ended the one account that re-synced its whole history on every launch.

A platform team at a 200-person company

Five product teams each ship a service. The platform team owns the gateway, the verifier and the policy folder. Each product team owns one file in api_configs/ and changes it in their own pull requests. CI runs npm run check, so a bad file never merges.

When finance asked that every import require an idempotency key, the platform team wrote an eight-line policy and the finance team added two lines to their route. /routes shows what is live. /metrics breaks requests down by service and route, so each team has its own dashboard without writing any code.
